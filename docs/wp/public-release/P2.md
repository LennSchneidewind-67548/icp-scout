## Why P2 looks the way it does

- Most of P2 can't happen in an implementer worktree. The worktree has no
  `private/`, so it has no leak terms and no `private/linkedin/`. Branch
  deletion and the flip are one-way and need the author's word. The social
  preview can only be uploaded in the web UI. So only the code and the build
  log go into a PR (part A). Everything else is a coordinator or author step,
  with the exact commands written out here.
- Part A needs the author's answers to the build-log gaps (N4), so the
  coordinator asks them first (step 1), and part A writes them in.
- The order makes the flip the last thing that can still be stopped. The leak
  sweep runs after the last pre-flip merge. A hit in history blocks the flip,
  because PR refs on GitHub can't be deleted by the repo owner.
- One small PR comes after the flip: the build-log entry for the go-public
  session. It records what happened, and its push is the CI run on the public
  repo that PLAN.md asks for.

## Step 2: the GitHub-text leak check (`scripts/leak-check-github.sh`)

Part A. PR titles and bodies, reviews and comments become public with the
repo, and `scripts/leak-check.sh` sees none of them (PLAN.md, Architecture 7).
This script runs the same terms over them. It is run by hand before the flip,
not in CI.

**Interface.** `bash scripts/leak-check-github.sh`, from the repo root.
Terms come from `$LEAK_TERMS` or, if that is empty, from
`private/leak-terms.txt`, exactly as in `scripts/leak-check.sh`: one term per
line, `\r` stripped, blank lines dropped, matched case-insensitively as fixed
strings (`grep -i -F -f`). No terms: print the same `::warning::` line as
`leak-check.sh` and exit 0. Exit codes: 0 when clean, 1 on any hit, 2 when a
`gh` call fails, so a network or auth error never reads as a pass.

**What it reads.** Each source is a `gh api --paginate <endpoint> --jq <expr>`
call. `gh` fills `{owner}/{repo}` from the git remote. The `--jq` filter
turns each item into one TSV line: an id, then the text fields. `@tsv`
escapes newlines, so each item is one line. No `jq` binary is needed, only
`gh`'s built-in filter.

| Kind (as printed) | Endpoint | Id | Text fields |
|---|---|---|---|
| PR | `repos/{owner}/{repo}/pulls?state=all&per_page=100` | `.number` | `.title`, `.body // ""`, `.head.ref` (the branch name) |
| review on PR | `repos/{owner}/{repo}/pulls/<n>/reviews?per_page=100`, for every PR number from the first call | `<n>` | `.body // ""` |
| review comment on PR | `repos/{owner}/{repo}/pulls/comments?per_page=100` | `.pull_request_url \| split("/") \| last` | `.body` |
| issue | `repos/{owner}/{repo}/issues?state=all&per_page=100`, `select(.pull_request \| not)` | `.number` | `.title`, `.body // ""` |
| comment on #<n> (issue or PR conversation) | `repos/{owner}/{repo}/issues/comments?per_page=100` | `.issue_url \| split("/") \| last` | `.body` |
| commit comment | `repos/{owner}/{repo}/comments?per_page=100` | `.commit_id[0:12]` | `.body` |
| release | `repos/{owner}/{repo}/releases?per_page=100` | `.tag_name` | `.name // ""`, `.body // ""` |
| repository | `repos/{owner}/{repo}` (no paginate) | `"repo"` | `.description // ""`, `(.topics \| join(" "))`, `.homepage // ""` |

**How it matches.** Each call writes to a temp file (one `mktemp`, removed by
a `trap`, as in `leak-check.sh`). If `gh` fails, the script prints
`Could not read <kind> from GitHub.` and exits 2. Then, for each line
(`while IFS=$'\t' read -r id text`), it greps the text against the terms. On a
hit it prints `Case-specific terms in <kind> <id>.`, for example
`Case-specific terms in PR #12.` It prints only kinds and ids, never the text
or the term, like `leak-check.sh`. At the end, when clean:
`GitHub text check passed: <t> terms, <p> PRs, <i> issues, <c> comments.`

The header comment says what it checks, that it prints no text, that it runs
by hand before a visibility change, and why: PR text and comments go public
with the repo, and `leak-check.sh` only reads git. About 70 lines.

**Test (`tests/test_leak_check_github.py`).** No network and no real terms.
A fixture writes a stub `gh` (a bash script) into `tmp_path / "bin"`. The stub
takes the endpoint argument after `api`, strips `repos/{owner}/{repo}` and
the query string, turns `/` into `_`, and prints `$STUB_DIR/<name>.tsv` if it
exists, or nothing. `repos/{owner}/{repo}` alone maps to `repo.tsv`;
`…/pulls/12/reviews` maps to `_pulls_12_reviews.tsv`, or whatever naming the
stub settles on. If `$STUB_DIR/fail` holds that name, the stub exits 1. The
canned files hold already-filtered TSV lines, so the test covers the
matching and reporting, not the `--jq` filters. The real run in "Local checks"
covers the filters. Each test runs
`subprocess.run(["bash", str(ROOT / "scripts" / "leak-check-github.sh")], cwd=tmp_path, env=…)`
with the stub's directory first on `PATH`. `cwd=tmp_path` means
`private/leak-terms.txt` is never read. The term is a made-up word,
e.g. `Zorblax`. Skip the module if `bash` isn't on `PATH`.

- Clean: no line holds the term. Exit 0, and "passed" is in the output.
- Hits: the term in PR #12's body, as `ZORBLAX` in PR #5's branch name, in a
  review comment on PR #7, in a comment on #3, and in the repository
  description. Exit 1. The output names `#12`, `#5`, `#7`, `#3` and
  `repository`, and neither stdout nor stderr contains the term in any case.
- A `gh` failure on the issue-comments call: exit 2, and the output says which
  kind couldn't be read.
- No terms (`LEAK_TERMS` empty, no `private/` under `tmp_path`): exit 0 with
  the warning.

## Risks

- **A hit in git history (step 5).** If the hit is only in a local ref, the
  flip can go ahead: check that `git branch -r --contains <commit>` is empty
  and that no `refs/pull-heads/*` contains it. If it is in a PR head or in
  `main`, it can't be undone by the owner: PR refs on GitHub are read-only
  and stay after a branch is deleted. Stop and ask the author. The options
  are GitHub Support removing the refs, or publishing a fresh repo without
  the history (which PLAN.md's "keep the history" decision would then have
  to give way to).
- **A hit in PR or comment text.** Editing the text isn't enough: GitHub
  keeps the edit history of PR bodies and comments, and anyone who can see
  the repo can open it. The fix is to edit the text, then delete the old
  revision from the "edited" menu. The author does that by hand in the web
  UI. Then run the check again.
- **An author answer carries case specifics** into the build log. The
  coordinator rewrites it before part A sees it. Part A checks again, and
  the main-checkout leak check before the merge catches named terms.
- **A `gh` error reads as a pass.** The script exits 2 when a call fails, and
  its "passed" line gives counts, so an empty fetch is visible.
- **A term split across a line break** in a PR body isn't matched, because
  `@tsv` turns newlines into `\n`. This is unlikely for names. Accepted.
- **The flip can't be taken back.** Once public, clones, forks and caches may
  exist. That's why it comes last, after every check, and only on the
  author's explicit yes.
- **LinkedIn shows an old or empty preview.** Post Inspector re-scrapes the
  URL. If the preview is still missing, check `og:image` (step 8) before
  anything else.
- **PRs from forks after the flip** run CI without the secret, so their leak
  check only warns. That's acceptable: the owner's pushes run with the
  secret, and the owner reviews fork PRs before merging.
